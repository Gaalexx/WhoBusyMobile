# WhoBusy

Мобильная доска планов и занятости по пространствам: Kotlin, Jetpack Compose, Ktor Client, Hilt с KSP и Navigation 3.

Приложение реализует [обновлённые 28 экранов Figma](https://www.figma.com/design/dDatbSFzoHbGIn2PWUqZnx?node-id=14-90): вход и регистрацию, общую доску день/неделя/месяц, пространства и приглашения, участников и роли, личные планы с отдельной видимостью, планы пространства, повторения, профиль. Дополнительно доступно управление аккаунтами глобальным администратором.

## Запуск

По умолчанию используются моки, без сетевых запросов. Поля входа заполнены: `demo@whobusy.test` / `demo1234` (также логин `demo`). Глобальный администратор: `admin` / `admin123`. Остальные демоаккаунты имеют пароль `demo1234`.

Демоучастник состоит в трёх пространствах с разными ролями и имеет приглашение в четвёртое. Даты планов вычисляются относительно текущего дня. В mock-режиме данные и сессия хранятся в памяти и сбрасываются с процессом. Регистрация сразу открывает сессию с пустым списком пространств.

- JDK 21 для Gradle daemon, JVM target 17.
- Android SDK Platform 37.1; путь в локальном `local.properties`.
- Gradle Wrapper 9.5.0, AGP 9.3.3; Kotlin встроен в AGP.
- Минимальный Android API 34, target SDK 36.

```bash
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest :app:lintDebug
./gradlew :app:connectedDebugAndroidTest
```

Последняя команда требует устройства/эмулятора. APK: `app/build/outputs/apk/debug/app-debug.apk`.

## Структура

- `app`: слои data, domain, di, presentation; UI-фичи разделены на ui, viewmodel, State и Command; завершение операций хранится в StateFlow до ResultHandled.
- `core:ui`: общие компоненты, стандартные Material Icons через UiIcon, цвета, тема и автономные Compose Preview.
- `WhoBusyApplication → MainActivity → WhoBusyApp → AppNavHost`: точка входа и типизированная Navigation 3. Три основные вкладки показывают плавающий бар поверх экрана, вложенные маршруты его скрывают.
- `MockAccountStore`, `MockWorkspaceRepository`, `MockCalendarRepository` используют общий набор аккаунтов, пространств, ролей и планов. Видимость и права проверяются в data до передачи UI.
- `RemoteAuthRepository`, `RemoteWorkspaceRepository`, `RemoteCalendarRepository` используют актуальный REST API; `RemoteSessionManager` управляет обновлением и восстановлением сессии. Access/профиль живут в памяти, refresh хранится зашифрованным через Android Keystore и DataStore в каталоге без backup.

Версии: `gradle/libs.versions.toml`. Для ИИ-агентов: [инструкции](AGENTS.md), [карта проекта](docs/AGENT_MAP.md), [источник дизайна](docs/DESIGN_REFERENCE.md).

## API

[API_CONTRACT.md](docs/API_CONTRACT.md) сверён с [FunProject, commit f828103](https://github.com/Gaalexx/FunProject/tree/f8281030dc268ddb94e93be290f6095858d8500d) от 17.10.2026, версия FastAPI — 2.0.0: регистрация, login/email, пространства, роли, приглашения, настройки доски и четыре уровня видимости планов.

Access JWT теперь действует 15 минут по умолчанию (`expires_in=900` в JSON). Refresh-token выдаётся только в `HttpOnly` cookie, ротируется при обновлении и имеет срок 30 дней. Добавлены `auth/refresh`, `auth/logout`, `auth/logout-all`; выход, смена/сброс пароля и блокировка отзывают refresh-сессии по правилам контракта. Native-клиент должен обрабатывать `Set-Cookie`, включая ротацию/удаление; refresh не передаётся полем JSON.

Пользовательский сервер и default base URL: [whobusy.ru](https://whobusy.ru/), `https://whobusy.ru/api/`. По умолчанию приложение использует моки. Удалённый режим переключает сразу все три репозитория — Auth, Workspace и Calendar:

```bash
./gradlew :app:assembleDebug -PwhoBusy.useMockData=false
```

Свой HTTPS-адрес можно задать через `-PwhoBusy.apiBaseUrl=https://<server>/api/`. Учётные данные и токены через Gradle не передаются; демологин в remote-форме не заполняется.

В исходниках реализованы регистрация/вход, зашифрованное сохранение refresh, восстановление при запуске, единое обновление access для параллельных 401 и однократный повтор запросов. До восстановления показывается загрузка; при временной ошибке доступны повтор и новый вход. Refresh передаётся вручную только выбранным auth-маршрутам этого API, а не через универсальный cookie jar.

Локальный выход очищает сохранённую сессию до возврата в экран входа; серверный отзыв выполняется в фоне и при отсутствии сети остаётся best effort. В профиле также есть «Выйти на всех устройствах» с подтверждением: повторный запрос и переходы блокируются на время выполнения, а при временной ошибке показывается сообщение и текущая сессия сохраняется.

Аварийное завершение между серверной ротацией и сохранением нового refresh может потребовать нового входа после истечения grace. Подробности и отличие logout от logout-all — в [контракте](docs/API_CONTRACT.md). Описание remote отражает код; результаты сборки, тестов и live-проверки фиксируются отдельно в [карте проекта](docs/AGENT_MAP.md).

Повторения поддерживают ежедневный режим, будни, недели, месяцы и годы, включая INTERVAL, COUNT и UNTIL для этого подмножества RRULE. Изменения/удаление относятся ко всей серии. Исключения отдельных вхождений и постоянный локальный кэш планов не реализованы; зашифрованное хранилище refresh существует отдельно.
